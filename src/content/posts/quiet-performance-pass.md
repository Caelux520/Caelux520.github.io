有时候优化并不需要重做页面。这次给自己划的范围很小：**只碰背景和元信息，不动组件结构**。最后挑了四件事，做完之后页面看起来几乎没变，但手机端和分享出去的样子都舒服了一点。

## 手机端：先让背景停下来

静态水纹原本用两个固定伪元素叠出来，一个 64 秒、一个 108 秒，缓慢地平移。单看很轻，但它们铺满全屏，又正好在固定导航和播放器的毛玻璃后面；背景每帧都在变，毛玻璃就得每帧重新采样。

所以第一步只是让手机端的背景停下来：

~~~css
@media (max-width: 768px) {
  html::after, body::after {
    animation: none;
    will-change: auto;
  }
}
~~~

观感几乎不变，水纹还在，只是不再漂。这一步解决的是待机时和固定栏的持续重采样。

至于滚动时卡片毛玻璃的开销，那是另一刀：把 .card 的 backdrop-filter 关掉、底色加厚。它会更进一步，但会明显改变手机卡片的观感，所以这次先没动。等真的觉得滚动不够跟手，再上。

## 水波：给最慢的设备一个出口

实时水波有一套自适应逻辑，但原来的阈值留了两个小洞：

- 只在 90 帧后评估一次，特别慢的机器要等很久才切静态；
- 降到最低分辨率后，要等到平均超过 62ms 才停，16 到 19fps 的设备会一直卡在中间。

现在的策略是：

- 首轮 30 帧就评估，之后每 90 帧一次；
- 平均超过 100ms，直接切静态；
- 最低档 0.42 后，平均超过 52ms 就切静态。

阈值不是理论算出来的，是看实际帧间隔调的。原则很简单：**宁可早一点回到静态水纹，也不要让用户盯着一片抖动的水**。

## 对比度：次要文字不是越淡越高级

亮色模式下，日期、统计小字、文章摘要用的都是 --text-dim。原来它是 #8a85a0，在淡紫卡片上只有 3 左右的对比度，小字号看起来很费劲。

这次把它调成 #5a5470，并删掉了手机端单独覆盖的 #6f6a85。现在：

- 卡片上大约 5.5:1；
- 直接落在渐变背景上大约 4.56:1；
- 暗色模式仍然是自己的 #b9b4cf，没有被误伤。

次要文字可以弱，但不该弱到需要眯眼。这个改动大概是四件事里最没有“技术含量”的，但阅读体验提升最直接。

## 分享卡：链接被粘贴出去时的门面

之前默认分享图用的是 640×640 的头像。链接发到聊天软件里，平台要么把图裁得很奇怪，要么缩成一小块，看起来不像一个认真维护的站点。

于是做了一张 1200×630 的默认分享卡：淡紫到淡蓝的底、头像、站名、标语和网址。然后在布局里补上：

~~~html
<meta property="og:image" content="..." />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:alt" content="..." />
<meta name="twitter:image:alt" content="..." />
~~~

默认页面用它，文章页继续用各自的封面；没有封面的文章才回落到这张卡。

做完才意识到一件事：**分享卡不需要站内有分享按钮**。它只是给平台抓取的元信息，别人复制地址、用浏览器分享、或者把链接粘贴进 Discord，都会触发。站内有没有一个“分享”按钮，和它生不生效是两回事。

当然，平台会缓存。换图之后，旧链接可能还是旧预览；测试时最好用公网地址，本地 192.168.x.x 平台是抓不到的。

## 验证与没做的事

这次改完只做了几项检查：

- 构建通过，页面正常生成；
- 手机端确认 animation-name 是 none、will-change 是 auto；
- 计算后的 --text-dim 是 #5a5470；
- 默认页的 OG 图是 1200×630，文章页仍然用自己的封面；
- 局域网地址能正常打开。

没做的是手机端卡片毛玻璃那一刀，以及其它没有列进这次范围的优化。留一点余地，比一次性把所有东西都改掉更稳妥。

背景可以很轻，但不应该廉价。这四件小事大概就是这句话的意思。
