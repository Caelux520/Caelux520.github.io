首页最底下原本是一层樱花。它也会轻轻飘，但看久了总觉得那是“一张图在动”，不是“水在流”。于是这次干脆把整层换掉，用 WebGL 每帧算一片水纹。

动手前只定了一条规矩：**只动最底层背景，卡片、导航、播放器一个不碰**；底下的淡紫到淡蓝渐变也原样保留。最后做出来的东西，应该像原本就长在那里，而不是又叠了一个特效。

## 为什么不直接用视频或贴图

视频最省事，但循环接缝、清晰度和体积都麻烦；一张贴图平移又很容易被看出是“同一块布在滑”。水纹真正好看的地方在于，它的高光会随着起伏变化，而不是整体位移。

所以这里用了一个全屏三角形 + fragment shader。WebGL1 就够，不需要额外框架；桌面端每帧算一次，移动端直接不初始化。

## 水面其实是一张高度场

先把屏幕坐标做宽高比校正，再乘一个尺度，得到采样空间。然后不是直接拿噪声当颜色，而是用两层 fBm 做域扭曲，得到一张缓慢流动的高度场：

~~~glsl
vec2 q = vec2(
  fbm(p + drift + vec2(0.035, 0.021) * t),
  fbm(p + drift + vec2(5.2, 1.3) - vec2(0.028, 0.030) * t)
);
vec2 r = vec2(
  fbm(p + drift + 2.0 * q + vec2(1.7, 9.2) + vec2(0.020, -0.016) * t),
  fbm(p + drift + 2.0 * q + vec2(8.3, 2.8) - vec2(0.018, 0.024) * t)
);
float h = fbm(p + drift + 1.8 * r);
h += 0.040 * noise(p * 5.5 + vec2(0.040, -0.030) * t + r * 1.4);
~~~

前两层负责大起伏，最后那行高频 noise 负责小褶皱。没有它，水面会像一块很干净的塑料；加上之后，光才有东西可以“抓”。

## 法线、高光和那层“湿”的感觉

高度场有了，接下来用屏幕空间导数求法线。这一步需要 OES_standard_derivatives 扩展，在 WebGL1 里要显式开启。

~~~glsl
vec2 grad = vec2(dFdx(h), dFdy(h)) * (170.0 * u_res.y / 620.0);
vec3 n = normalize(vec3(-grad, 1.0));
vec3 L = normalize(vec3(-0.55, -0.58, 0.60));
float diff = max(dot(n, L), 0.0);
float spec = pow(diff, 48.0);
float relief = smoothstep(0.32, 1.0, diff);
~~~

那个 170.0 * u_res.y / 620.0 是调出来的。固定乘一个常数的话，换分辨率水面就会突然变平或者变成刀片；按高度归一化之后，同一片水在 1080p 和 2K 上看起来才差不多。

颜色没有用真实水体那种深蓝，而是取了偏青的深色和接近白色的亮色：

~~~glsl
vec3 deep  = vec3(0.34, 0.70, 0.86);
vec3 light = vec3(0.91, 0.99, 1.00);
vec3 col = mix(deep, light, clamp(relief * 0.7 + spec, 0.0, 1.0));
~~~

透明度由三部分组成：一层很薄的底色、按起伏增强的亮度、以及很窄的高光。最后 clamp 到 0.62，避免在某些屏幕上白成一片。

输出用了**预乘 alpha**：

~~~glsl
gl_FragColor = vec4(col * a, a);
~~~

对应的混合方式是 ONE / ONE_MINUS_SRC_ALPHA。如果按普通 alpha 输出，浏览器合成时还会再乘一次，亮部边缘容易发灰发暗；预乘之后，透明和颜色是一起送进去的。

## 让它在慢设备上体面地退场

实时水波再轻，也是每帧一次 fragment shader。所以一开始就给它设了上限：

- 内部渲染分辨率先按 0.78 倍算，DPR 最多 1.25；
- 帧率限制在 30fps，水面很慢，没必要追 60；
- 首轮只采样 30 帧，之后每 90 帧评估一次平均帧间隔；
- 平均超过 100ms（不到 10fps）直接切静态，不再慢慢降档；
- 分辨率降到 0.42 后，如果平均还是超过 52ms，也切静态，不再卡在 16 到 19fps 的尴尬区间。

真正停掉的时候，不是把 canvas 一藏了事，而是移除 water-live 类，让 CSS 里那张静态水纹重新露出来。静态水纹本来就是按“水”画的，所以退场之后看起来仍然是同一个背景，只是不流了。

## 切页之后，别把旧 canvas 的魂招回来

站点用了 Astro 的 ClientRouter，切页不是整页刷新。这里踩过一个很隐蔽的坑：旧 canvas 被替换时会发 webglcontextlost，如果监听器不区分事件来源，就会把新 canvas 的循环一起关掉。

最后的处理是：

- onLost 里先判断 e.target === state.canvas，不是当前画布就直接返回；
- stop() 时移除监听、清空画布、删除 program 和 buffer；
- 只有 canvas 已经不在文档里时，才主动 loseContext()，避免影响下一次初始化。

这类问题在单页应用里很常见：特效本身没问题，错的是生命周期。

## 最后

现在桌面端看到的是一片实时计算的水，手机端、触屏和开了“减少动态效果”的设备则继续用静态水纹。后者不是失败后的兜底，而是有意保留的另一种呈现——手机不该为了一层背景多付 GPU。

下次如果再折腾，可能会试试让水面对鼠标有反应；但那是另一个故事了。至少这一次，背景终于不是“贴上去的”，而是算出来的。
